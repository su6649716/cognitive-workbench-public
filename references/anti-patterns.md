# 已有失败模式与定向处理

保留原十种失败模式。不把此表变成每次必须输出的安全报告；只有命中且影响当前结果才处理。

| 原模式 | 定向处理 |
|---|---|
| 静默建档 | 先查同项目/问题/阶段，无新事实只续接 |
| 点名即建档 | 调用不等于事件，简单任务直接完成 |
| 重复收口 | 同阶段一条 task_close，后续 update |
| 推断冒充确认 | assistant_inferred 与 user_explicit/user_confirmed 分开 |
| 补写未经确认的决定 | 不为账面完整补造阈值、来源或决定 |
| 能力覆盖率表演 | 仅保留实际改变决定的可核对依据 |
| 认知结论替代工程检查 | 读取 closure.ready，同时保留功能验收证据 |
| 证据等级超标 | L1/L2/L3分开，不以静态检查声称真实生产可用 |
| 活动代理当投入 | 调用/文件数不是用户工时、收益或价值 |
| 追踪不回看 | 相关项目按 due/trigger 回看；不按次数自动关闭 |

本次有来源的补充：本线程 T05 首轮候选出现“指出问题但仍沿原路线交付”；主文件要求在证据、确认和授权允许时让选路改变主交付。本条不证明 D 已稳定优于基础模型。

同步 S01—S07、状态/工程 C01—C07 来自审计方案；修复与测试记录在交付包 verification/，不将它们改写为已经发生在用户生产环境中的事故。
