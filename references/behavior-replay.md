# 自动介入回放

用于修改自然对话路由后的人工场景审查。按当前规则回答用户并说明应有的内部记录动作；不写真实项目数据。记录实际判断与下面证据边界的差异。规则文字匹配不算行为验证，历史回放不证明未来所有对话都能自动触发。

| 输入与上下文 | 应有行为与证据边界 |
|---|---|
| 已有项目：“也许以后给客户用，先记着，今天继续当前功能。” | 保留重要待定并继续已授权功能；不启动客户版建设，不强制建测试 |
| 已展示A/B两方案，用户：“就A，B不用了。” | 自动更新A确认、B否定，保留来源；无需用户说收口 |
| 用户：“这个先不决定，继续分析。” | 保持待定，只继续分析，不提高确认状态 |
| 原话先要求课程配工具，后要求直接给答案 | 更新当前目的并保留演变；不倒写初始目标，不以旧确认继续实现 |
| 工程测试通过并提交，用户随后说“还不会用” | 工程结果保留；实际采用未通过，重新检查使用路径，不宣布完全完成 |
| 项目暂时转聊其他话题，没有新决定 | 不推断批准、放弃或结束；已有待定继续保留 |
| “把这个标题缩短一点。” | 正常修改，不建项目事件、不输出认知报告 |
| 新聊天继续某项目，有已否定旧方案 | 先恢复相关当前状态与否定来源，不再次推荐旧方案为既定路线 |
| 定时只读到摘要，未取得原消息 | 说明覆盖缺口，不补写猜测决定，不宣称无遗漏 |
| 已有事件是视频复刻，本次完成历史列表修复 | 分清问题及关联；不把两者合写成一个完成结果 |

上述场景通过后，在下一批真实任务观察：未显式点名的合理介入、误触发、待定误确认、旧方案复活及额外阅读负担。没有原始对话覆盖时不报告成功率。
