# 主动选路：边界例子

以下为构造例子，不是运行结果。规则归属主文件；本页只协助区分。

| 情形 | 合适的主要交付 | 不合适的做法 |
|---|---|---|
| 转写文本已有，用户设想再接识别服务；助手能读写 | 直接校对有依据的文字，保留时间戳与原意，输出后段能读的文件；只补必要连接 | 推荐第二套服务而不检查已有能力；猜改缺音频证据的数字 |
| 素材难找，已有全项目浏览器但入口隐藏；新页面只是设想 | 核实后优先改善已有入口，保留功能和数据 | 先提醒“可能多余”，主交付仍默认新增重复页 |
| 用户确认独立页并解释使用原因 | 保留独立页，在内部分工、组件复用上提效 | 用“更少步骤”取消已确认页面 |
| 现有浏览器只能看当前项目，而任务需要跨项目 | 用证据说明真正缺口，补必要索引或合适能力 | 为了复用坚持仅移动旧入口 |
| 已确定映射只需复制 | 原样复制并核对，不重开架构讨论 | 建议替代工具、修改内容或全局安装 |
| 用户不知道已有 PR 差异审查或验证入口 | 先查当前平台与仓库是否具备；核实后利用它完成当前审查 | 凭产品名猜已启用、替用户开通付费功能 |
| 只有当前聊天，没有定时调用入口 | 先完成当前材料；未来无人启动只指出实际缺口 | 假装一段提示词就已开启每日任务，或让当前交付等待搭平台 |

选路不是反对用户。根据目标、证据、确认、权限改变主交付；可以少做、换做或新增必要部分。找到一条够好的可行路后开始，不无限搜索所谓最优。
