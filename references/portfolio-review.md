# 多项目下注复盘

只在明确请求比较多项目、既有定时任务或明确要求比较在途工作的新增项目决策时运行。不因某项目到期抢占当前任务。

## 输入

用户明确状态、相关任务记录与项目文件、决定与实验、实际产物与变化。线程数、改文件数和调用次数只能是活动代理，不能推断用户工时、价值或线下投入。

## 取舍

合并同项目别名；区分主业务、验证、维护、内容生产、临时探索、长期停滞。用项目索引和事件查询恢复现状，检查有活动无结果的项目；不把 task_close 存在当已交付，代码还看实际检查点。

比较新增事项挤占的最佳替代项。识别争用用户时间、开发并发、发布窗口和预算的项目，提出谁让路、让到何时、期间最小维持动作；不要只说“都重要”。继续/暂停/结束/观察给推荐与代价，长期停滞且无人认领先标待决定，不擅自判死刑。

## 输出与记录

给本周主攻、验证中、维护、探索、停滞和真正影响取舍的证据缺口；最多一至三个需要用户决定的分叉。留下自然回看条件，可为日期、结果出现或下次立项。

确认取舍后记录 portfolio_review metadata；未经确认不修改项目状态、归档、关闭任务或自动化。写入和去重按事件生命周期。
