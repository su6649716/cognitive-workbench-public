# 多项目下注复盘

## 目的

让新增项目的机会成本、停滞项目和探索出口可见。不是生成任务清单，也不根据Codex活动假装知道真实经营投入。

## 信息来源

优先使用：

- 用户明确提供的项目状态；
- 最近Codex任务与项目文件；
- 已记录的决定、实验和到期结果；
- 可验证的交付物与变更。

把线程数、文件数、修改频率标为“活动代理”，不能直接翻译成工时、价值或进度。

## 操作

1. 合并同一项目的不同任务名称。
2. 区分主业务、正在验证、维护修复、内容生产、临时探索和长期停滞。
3. 找出有活动但缺少结果证据的项目。
   - 先用 `cognitive_ledger.py audit` 找未关联任务、缺少回看点和重复事件。
   - 用 `project_index.py list` 合并中文名、代码目录名和不同任务标题指向的同一项目。
4. 找出新增项目将挤占的最佳替代项。
5. 对每个候选只提出继续、暂停、结束或保持观察，不代替用户决定。
6. 最多要求用户回答三个取舍问题。
7. 不把“有 task_close 记录”直接等同于项目已交付；代码项目还要核对提交和工程收口状态。

## 输出

```text
本周主攻：
正在验证：
维护与修复：
临时探索：
长期停滞：
证据缺口：

需要用户决定：
1.
2.
3.
```

## 定时整理

定时任务明确授权整理时，在已有项目索引和事件账本内工作，优先更新同职责自动任务。保留原回顾职责，并检查自上次可核实检查点以来的相关变化；首次可限定最近一周。无法读取的任务记录为覆盖缺口，不推断“没有变化”。

- 对照原始用户消息检查漏记的明确决定、待定和否定；只读摘要不足时继续获取相关原文。
- 核对项目检查点、规划状态和事件结果；提交不证明用户接受，长时间未动不证明项目结束。
- 检查跨问题混写、重复和已被替代的路线；有来源的事实维护通过追加更新完成，保留历史。含糊关联只列待核对项。
- 对没有新事实的待定项保持原状态；只有自然回看条件已满足、到期或影响当前工作时才提醒。
- 不自动修改Skill或全局规则、不删除历史、不合并身份含糊的项目、不替用户改变目标或决定项目去留。运行前重读目标记录，避免覆盖期间新增内容；写后复核。

`audit` 的healthy只代表结构检查通过，不证明语义一致、用户满意或自动触发没有遗漏。输出保留简短工作回顾，仅增加有实质变化、需决定或执行失败的内容，不重复贴全部账本。

## 取舍记录

用户确认取舍后记录 `portfolio_review`，并把项目级继续、暂停、结束决定放入 `metadata`。未经确认不修改项目、归档任务或关闭自动化。
