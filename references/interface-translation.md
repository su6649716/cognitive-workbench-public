# 界面转译：把规划变成可连续操作的表面

## 定位

界面转译是 `expansion_gate` 的系统一致性分支中的条件步骤，不是第五个工作流，也不是通用视觉设计 Skill。

它负责把已经确认的用户目的、组件职责、真实规则和连续使用路径，翻译成用户能看懂、能操作、能判断下一步、失败后能恢复的应用、网页、工作台、表格或操作型课件。目标不是先做漂亮，而是让业务逻辑在界面上成立。目的或产品形态尚未确认且返工成本高时，先进入 [collaborative-definition.md](collaborative-definition.md)。

## 何时使用

满足任一情况时使用：

- 新建或重做面向人持续操作、判断、录入的界面；
- 用户说看不懂、不连贯、不知道下一步、无法日常使用；
- 当前成品只有数据或功能，但缺少连续操作、状态反馈、异常恢复；
- 表格虽然数据完整，却存在列关系难辨、输入与结果混杂、合并单元格妨碍操作等问题；
- 用户纠正了产品形态，例如从资料展示改为地图、向导、计算器、工作台或生产队列。

普通后端修改、普通文章排版、一次性展示页和不改变使用逻辑的颜色微调不使用。

## 先选择操作形态

不要先选组件、颜色或页面数量。根据真实工作的结构选择形态：

- 有明确状态变化、通关条件和失败退路：地图、向导或状态机；
- 围绕一组输入得到计算和判断：计算器或表单工作台；
- 高频核对大量同类事实：清晰网格、筛选表或主从表；
- 多任务并行、排队、失败、恢复和结果落地：队列与监控工作台；
- 需要比较候选并作决定：对比与决策面板。

这些是选择依据，不是固定模板。不要把一个项目成功的形态强行复制到其他项目。

## 从任务到界面

用一个真实任务样本依次回答：

1. 用户在什么情境进入，带着什么真实输入；
2. 首屏必须让他知道什么、先做什么；
3. 哪些是来源事实、哪些允许编辑、哪些由系统计算；
4. 当前唯一主要动作是什么，动作后状态怎样变化；
5. 下一步如何承接上一步的数据，不让用户重复抄写或重新理解；
6. 什么结果算完成，界面怎样明确显示；
7. 失败、缺失、冲突或中断时，怎样说明原因并回到可继续状态。

术语若不能直接指导动作，要转成后台对象、输入、操作和核对结果。不要用说明文字掩盖缺失的交互。

## 界面合同

实现前形成一份紧凑合同，简单项目可以合并表达：

```text
使用者与单次任务：
首屏目标与唯一主动作：
连续操作路径：
页面/区域及信息优先级：
来源事实、可编辑输入、系统结果如何区分：
完成状态与下一步：
异常、失败与恢复：
视觉语义和已确认偏好：
```

合同只保存影响使用的决定，不写具体 CSS 清单或完整组件树。用户已确认且会跨任务复用时，将紧凑版本写入项目索引的 `interface_baseline`；单个页面的临时偏好留在当前任务，不自动升级为全局偏好。

## 视觉语义

颜色、框线、字号、间距和对齐用于表达业务含义，而不是独立装饰：

- 用稳定差异区分只读事实、可编辑输入、系统计算结果、待确认和异常；
- 框线、留白和分组必须让标题、行、列、对象与结果关系清晰；
- 主要动作只保留一个最高视觉优先级，次要动作不得竞争；
- 高频经营表优先可扫描、可筛选、可复制和可持续维护，谨慎使用合并单元格；
- 错误出现在发生问题的对象旁边，并提供原因、影响和恢复动作；
- 不把某个项目的黑白灰、黄色或红色规则写成所有产品的强制配色，除非用户明确确认其为全局偏好。

## 实施前预演

在大规模开发前，用真实或忠实样本走完一轮低成本预演：

```text
进入 → 找到当前任务 → 输入/选择 → 系统处理
→ 核对结果 → 完成/进入下一步 → 失败后恢复
```

预演重点检查：

- 完全不懂领域的人能否知道下一步；
- 有没有需要用户自己猜、自己算、自己记忆的隐藏动作；
- 上一步数据是否自动进入下一步；
- 产品是否越过了规划主线中的组件边界；
- 界面是否只有“功能存在”，却没有可观察的完成状态。

低风险小界面可以直接实现后验证；复杂、高返工成本或用户已经多次纠正的界面，应先产出用户可见的低保真结构或代表性样板，用真实任务路径验证首屏、主动作、状态变化、完成和恢复，再扩到完整版本。

代表性样板不是缩小版成品展示，而是验证最危险的产品与界面决定。进入完整实现前记录 `sample_status=accepted`；确实不需要样板时记录 `sample_status=not_required` 和原因。用户说“直接做”且已经看见并确认目的、形态和范围时可立即继续；尚未展示的系统推断不能只靠内部预演跳过确认。

## 验收与边界

验收至少区分：

- **任务成立**：用户能连续完成一次真实任务；
- **规则成立**：输入、计算、状态和边界符合事实真源；
- **界面成立**：能分清现在做什么、结果是什么、下一步是什么、失败如何恢复；
- **视觉成立**：颜色、框线、层级和密度服务于上述语义。

完整开发之后仍要做真实使用验证。样板确认只证明双方对路线理解一致，不能代替用户在真实任务中判断“好不好用”。真实反馈若改变操作语义，返回共同定义中受影响的一层，而不是继续堆视觉补丁。

认知助手负责界面合同和验收标准；实际网页、表格、演示文稿或应用实现继续使用对应工具与 Skill。不要因为进入界面转译而自动增加账号、云同步、动画、设计系统或其他未确认基础设施。

## 真实回归样例

### 课程操作工具

如果目标是让没听过课程的人完成操作，界面要围绕当前关卡、填写内容、系统计算、通关条件和修复支线，而不是围绕课程原话、案例来源和术语解释。

### 商品成本表

如果当前职责只是成本和 SKU 决策，界面应突出产品或固定组合选择、不可修改的来源事实、允许填写的数量、自动成本与定价结果；图片上传和平台发布仍留在下游。

### 本地图片生产工具

如果目标是稳定完成多任务生产，界面应让用户看到不同工作室能否同时提交、每张图的真实状态、失败原因、恢复动作和本地保存位置，而不是只显示一个批次级“失败”。
