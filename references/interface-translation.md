# 界面转译：连续任务到可操作表面

## 定位

这是系统一致性的条件步骤，不是第五个工作流，也不是通用视觉设计系统。负责让用户看懂、能操作、知道下一步、失败后可恢复；具体网页、表格、演示或应用使用对应能力。关键产品语义未明且返工昂贵时，按共同定义，不另设确认规则。

持续操作界面的新建/重做、用户说不连贯或不知道下一步、功能有而状态与恢复没有、输入与结果混杂、产品形态被纠正时使用。后端小修、文章排版、一次性展示和仅改配色不自动进入。

## 先选择操作形态

状态变化、通关和失败退路可用地图/向导/状态机；一组输入到计算判断可用计算器/表单工作台；高频核对同类事实用网格/筛选/主从表；并行生产用队列与监控；候选取舍用比较面板。按真实工作选择，不把单项目成功模板推广为全局规则。

## 真实任务样本

取得用户情境和输入；明确首屏应知道什么、当前主要动作是什么；区分事实、编辑和计算；描绘动作后的状态；让上一步数据直接承接下一步；定义完成；缺失、冲突、失败与中断必须有恢复路径。术语转成对象、输入、动作和核对结果，不能用说明文字掩盖缺交互。

## 界面合同

合同保留影响使用的决定：

- 使用者与单次任务、首屏目标和唯一最高优先级主动作；
- 连续操作路径、页面/区域和信息优先级；
- 来源事实、可编辑输入、系统结果如何区分；
- 完成状态、下一步、失败与恢复；
- 视觉语义与已确认偏好。

合同不是 CSS 清单或完整组件树。实际字号、间距、颜色、公共控件和状态按 [项目工程规范](project-baseline.md) 落到当前选定的主题与组件。全新设计依据本轮目标和视觉要求，不默认复刻旧界面；需要起点时按需读 [条件默认值](project-baseline-defaults.md#界面与交互)，不要把浅色表格强加给所有项目。维护任务才沿用仍适用的现行视觉规范。

稳定且允许写入时保存 `interface_baseline`；临时页面偏好不提升为用户全局偏好。

## 视觉语义

颜色、框线、字号、留白、对齐服务于业务：稳定地区分事实、可编辑、计算、待确认、异常；让标题/行/列关系清楚；次要动作不抢主动作；高频表格能扫读、筛选、复制、维护，谨慎合并单元格；错误邻近对象显示原因、影响和恢复。没有用户明确确认，不强制所有产品同一配色。

## 预演与验收

以真实或忠实样本走完“进入→找到任务→输入/选择→处理→核对→完成/下一步→失败恢复”。检查零领域背景的人能否继续，是否需要自己猜/算/记，上步数据是否承接，是否越过组件边界，是否有可观察完成状态。

低风险可先实现后验证；复杂或反复返工时先做可见低保真或代表性样板，验证最危险决定再扩展。样板是否必须、接受和跳过理由以共同定义为准，不在此再要求一轮确认。

验收分为任务成立、规则成立、界面成立、视觉成立；样板确认不代替实际使用。真实反馈改变操作语义时回到原定义受影响层，不继续堆视觉补丁。不要因为进入界面转译而自动增加账号、云同步、动画或设计系统。

## 场景例子

课程操作工具围绕关卡、填写、计算、通关与修复，不围绕原文术语堆展示。
商品成本表突出产品/组合、来源事实、数量、成本定价，上传发布留在下游。
本地图片生产工具显示各工作室并行任务、每图真实状态、失败原因、恢复和本地保存，不只给批次级“失败”。
