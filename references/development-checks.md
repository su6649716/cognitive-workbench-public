# 开发一致性检查：定稿边界、同类纠正、实际验收

这是每轮项目开发的执行要求，嵌入既有开工、纠正和收尾步骤，不新增工作流、后台服务或重复审批。按任务相关性取用；已有明确授权直接执行，用户已确定的内容不重新提问。只读审计仅核对事实，不因本检查写项目、状态或规则。

## 开工：把定稿保护到实际运行效果

- 从用户最新要求恢复已定稿、可改、禁改和候选待定内容，保留各自来源。界面升级、按稿还原、功能接入分别识别；升级授权不自动允许重新设计。候选稿进入画板供查看，不等于获准替代定稿或接入业务。
- 明确受保护的设计资源、页面、功能和视觉角色。定稿角色包括布局、字体及字号/字重/行高/字距、组件、颜色语义；仅核对任务涉及的项。项目特定的封面、术语、配色等限制留在该项目，不推广成所有产品的规则。
- 从真实入口追踪样式、脚本、路由、共享组件及其覆盖顺序，检查全局选择器、补丁样式和共享依赖会不会影响禁改页面。不能只扫描名称像“本模块”的文件，也不能以原设计文件或组件源未改为由宣布运行页面未变。
- 对照定稿建立受影响页面的区块、字段、状态和功能入口映射，复用当前已确认角色。保留真实业务能力，不把设计示例数字和预览模拟逻辑复制为业务事实。无法映射的差异先查现有实现和依据，不自行补设计。
- 多页落地或反复偏离时，先用既有定稿中的代表页验证映射和依赖影响，再按同一方法展开；不另造样板方向，也不为已确定的技术细节增加确认。

## 纠正：把用户举例还原成问题类别

1. 识别纠正属于定稿边界、术语/数据语义、组件/视觉、功能、性能还是交付入口，找共同原因。
2. 用户指出一处示例时，搜索全部同类页面、共享组件、数据状态与入口，检查同一机制的消费者；不能仅修选中节点、当前截图或刚改的文件。范围确实被用户限定时遵守限定。
3. 区分应该修复、已一致和有依据的例外。审计范围可以覆盖全部同类对象，实际修改只落在不符合要求的地方；不把全量检查扩成全页重设计。
4. 在现有任务记录中保留必要的检查范围、发现和例外依据，使后续 Agent 可核对。先处理共同原因，再复检关联页面，不能用反复追加覆盖样式维持表面一致。

## 收尾：要求、实际对象和证据一一对应

| 用户要求 | 应取得的证据 | 单独不能证明完成的材料 |
|---|---|---|
| 按已确定设计还原、保护其他页面 | 实际运行版本的页面，在可比窗口和明确数据/状态下与定稿逐页对照；受影响的保护页面也复检 | 原稿哈希未变、组件文件没改、只看静态 HTML 或测试全绿 |
| 功能别丢 | 对应入口和代表性操作链，以及相关权限、保存、确认、失败/未知等必要状态的验证 | 页面截图、按钮名称存在 |
| 修正一类问题 | 全部同类对象的检查结果与必要修复、例外依据 | 只修用户圈出的一处 |
| 数据增加后可用、性能改善 | 在用户要求的数据量和相关状态下检查读取、渲染、滚动、筛选/分页及刷新；性能结论使用实际测量口径 | 小数据空态正常、后端 benchmark、没有测量的“丝滑/FPS/INP”结论 |
| 保存、迁移并打开可见结果 | 从用户实际使用的入口打开，核对目录/数量/顺序、依赖加载和打开预览路径 | 文件复制成功、归档数量正确但没有挂到入口 |

- UI 验收先确认打开的是正确项目、版本、页面、窗口和数据范围，等相关数据加载后检查；不能用另一个预览、旧截图或空态代替真实目标。
- 用户要求逐页或全量对照时，覆盖指定页面并列出剩余项；只验证样板不能声称全部页面一致。动态数据造成的合理差异须解释依据，不能默默改布局消除差异。
- 本地合成场景、自动测试、真实账号/生产使用分别报告。浏览器可视检查、功能回归和性能采样各自证明其覆盖内容，不能互相替代。
- 缺少实际页面或必要状态证据时，先利用已有能力补证；仍无法取得则明确“已实现、该项未验收”及具体缺口，不宣布全部完成。Git 的 `closure.ready` 只证明工程检查点，仍需对应任务验收。

## 自动接入与证据边界

项目 `begin` / `peek` 及已启用的生命周期钩子返回三项检查入口，状态始终是尚未执行的要求；恢复要求不代表已经检查通过。Agent 在开发、收到纠正和收尾时主动调用适用工具取得证据。未启用钩子的宿主仍按主文件执行；不因写了规则就声称后台监控或无人视觉验收已运行。

本规则来自一次已确认定稿落地的失败复盘：共享样式影响禁改页面、同类纠正遗漏、工程证据被扩大为页面完成，以及已归档内容没有出现在用户入口。只保存可复用判断，不带入该项目的具体设计值或业务代码。
