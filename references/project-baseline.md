# 项目工程规范

## 职责

把当前目标转成可执行的架构、契约、UI、异常恢复和运行约定，落实到项目并服务当前交付。这是认知助手的内置能力，不需要另外安装或调用其他 Skill，也不增加主工作流。用户没逐项提出字号、接口、日志或恢复要求，不等于可以忽略必要的工程决定。

主文件裁决全新建设与维护任务的边界。本文件负责具体取值、文档和实现落点；[架构基线](architecture-baseline.md)检查职责与依赖，[工程基线](engineering-baseline.md)负责 Git 起点与收口。

## 1. 按当前任务建立依据

| 当前任务 | 做法 |
|---|---|
| 全新项目、全新重做、明确不沿用旧方案 | 直接根据当前目标设计。不默认继承旧架构、旧页面、旧字段、旧基线或旧模板；不为旧实现保留兼容层。 |
| 维护现有系统或明确局部重构 | 核实当前真实使用与有效约定，处理本次相关部分；失效规范不因已经存在就继续有效。 |
| 原型转生产 | 以目标生产场景重新审视架构与运行要求；原型是验证材料，不是必须沿用的架构。 |
| 小修复、文案、机械修改 | 直接完成当前任务，不附加整套规范建设。 |

读取对当前决定有用的材料，不为“恢复历史”扫描所有旧文件。适用依据为：**当前目标与明确约束 → 当前事实与使用场景 → 适用的工程选择与条件默认值**。历史方案只有经过重新验证、且本轮确实采用的部分才进入新基线。用户已说明全新建设，不重复让用户否定同一旧方案。

“全新”不改变已存在的数据所有权、真实外部消费者或操作授权；确实存在这些承接责任时，单独处理必要接口/数据，不因此恢复旧产品整套设计。没有实际承接对象，就不制造兼容、迁移和回退旧架构的任务。

## 2. 主动选定具体做法

按需读 [条件默认值](project-baseline-defaults.md)，采用一个符合当前目标的具体选择，说明关键理由。默认值是起点，不是强制标准；不以“附件原样保留”为目标。常规技术决定由助手完成，不把选项清单推回用户。上游协议、价格、版本和限额需要真实依据；缺业务事实或重要授权时只处理被影响的动作。

按适用性覆盖：

- 各部分在哪里运行、模块公共入口、依赖方向、数据校验与写入责任；
- 技术、配置与版本确认，字段、状态、时间、单位、权限和错误的唯一契约；
- 有 UI 时选定具体字号、间距、颜色、公共控件及加载/空数据/执行中/成功/失败恢复；
- 新增或修改 UI 组件时，按 [组件容量与内容边界](development-checks.md#组件容量与内容边界新增或修改-ui-时主动执行) 选定数量、长内容和窄容器的公共处理与完整访问入口；具体值及验证落到当前项目，不只处理正常短样例；
- 有外部服务时决定适配入口、凭据位置、输入限制、超时、重试、幂等、核对和取消含义；
- 适用的日志诊断、健康信号、用量预算、发布、备份与恢复；
- 一条代表流程的输入、交接、关键失败、恢复和完成条件，以及后续模块的接入入口。

无需对应能力时直接裁剪，不向用户汇报整份“尚未实现”清单。前后端职责分离不自动意味着分仓、独立部署或微服务。

## 3. 落到当前项目的一套规范

全新项目建立 `docs/PROJECT_BASELINE.md`；维护任务更新本次核实仍有效的权威文件。用 [基线骨架](../assets/project-baseline/PROJECT_BASELINE.md) 辅助填写，而非将旧文档或模板当答案。

每个适用决定包含：**具体选择、依据、权威定义所在位置、当前状态、验证证据或下一动作**。删除提示和不适用项；空白骨架、口号、目录清单不构成交付。状态区分**已确定、已实现、已验证**；不存在的路径标为“拟建”。这三个状态不替代用户确认字段，不把技术选择写成 `user_confirmed`。

实现后让契约、主题、组件或配置成为实际值的真源，文档引用它们。后续模块继承的是本次明确建立的规范，而不是旧项目包袱。确需修改公共约定时同步其使用方，不维护两套互相冲突的定义。

本轮允许写项目文档时，用 [项目入口片段](../assets/project-baseline/AGENT_ENTRY.md) 创建或更新**项目级** `AGENTS.md`，指向本次权威文件。同职责段落不重复追加；被本轮明确替代的工程要求须更新，不原封不动保留冲突段落。不相关内容和有效安全/授权约束保持有效。全新独立目录不复制旧项目入口。

不修改 `~/.codex/AGENTS.md` 等全局配置；项目规则不是全局安装。只读审查不因发现缺基线而写文档、入口或索引。只允许交付设计而不允许修改项目时，将可用内容交到指定位置，不冒充已经接入。

## 4. 按规范继续完成工作

用户要设计，交具体设计；用户要实现，继续完成当前功能，**开发任务不能只交规范**。

为当前功能建立必要的契约、主题变量、客户端、业务入口或适配层。可复用当前已验证且符合新目标的能力，不为了“不沿用旧的”重复制造可靠通用工具，也不为了“复用”把不适合的旧结构搬进来。

先跑通“输入/操作 → 业务处理 → 适用的数据/外部服务 → 结果反馈”及关键失败恢复，再扩其他模块。不预建空层或未使用组件库。页面布局可以不同，共同字段、设计变量、错误语义和运行规则保持一致。

公共约定变动时同步当前实际使用方与验证；仅在确有存量消费者或数据承接时做兼容处理。内部变化在所属模块解决，小修不附带全局重写。能稳定检查的约束接入工具链，不能机械检查的用具体验收，不把提示词当检查器。

## 5. 交付与记忆

工程约定改变后，按 [知识收尾](knowledge-closeout.md) 核对当前基线、实现、Agent 入口与实际使用方。不在每处复制规范；入口指向同一真源，被替换的现役说法就地修正。文件存在不等于加载生效，需当前宿主可用的加载证据。

**设计：**具体决定与代表流程成立，拟建/真实路径明确，入口指向有效文件。

**实现：**功能及关键失败经过实际检查，共用定义确实被使用，相关测试/构建成立。

**生产：**适用的配置、日志、发布和恢复有对应证据；模拟不冒充真实依赖。只报告影响当前使用的缺口。

已核实文档可按授权登记到项目索引 `product_docs`；规划和界面决定存入该项目 `planning_baseline`、`interface_baseline`。全新项目核实自己的名称与源码根；检索命中旧项目只是候选，不自动合并身份或继承其决定。不新建记忆库。重要阶段只收口一次，其余继续当前任务。
