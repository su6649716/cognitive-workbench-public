# 私有状态同步与恢复

2.4 是全新独立状态根：`~/.cognitive-workbench/`。**不会绑定或读取旧 `cognitive-workbench-state` 私有仓库。** 如需远端备份，应由用户明确创建或指定一个新的私有状态仓库并授权同步；源码与状态仍分别管理。私有 GitHub 仓库也属于外部存储。

## 授权与入口

仅明确同步请求或原项目有效自动推送策略允许时运行 --push；只读任务不因 Skill 触发就同步。测试使用隔离合成目录和本地裸仓库，不触碰真实个人状态。

```text
python3 <SKILL_DIR>/scripts/sync_state.py --codex-home <状态根> --repo <状态仓库根> --dry-run
python3 <SKILL_DIR>/scripts/sync_state.py --codex-home <状态根> --repo <状态仓库根>
python3 <SKILL_DIR>/scripts/sync_state.py --codex-home <状态根> --repo <状态仓库根> --push
```

默认目标 origin/main；不同目标须显式 --remote / --branch，并先确认授权。当前分支必须匹配，detached 或不匹配在写入前拒绝。脚本不创建仓库、不改远端、不改源文件。

## 受管集合与真实回执

只接收 2.4 的 `STATE_INFO.json`（全新状态身份）、`PROJECT_INDEX.json`、`COGNITIVE_EVENTS.jsonl`，以及当状态根中真实存在时才纳入的 `AGENTS.md` 和 `automations/<id>/automation.toml`。结构验证和常见密钥扫描使用同一份内存字节；实际暂存字节必须与这份内容相同。扫描不是万能密钥检测器，仍应按最小内容原则存储。

仅暂存精确文件/受管删除；额外文件不带走。原暂存区非空直接拒绝且不清空；目标受管文件有独立修改不覆盖。同步锁防止本工具自身并发，不宣称隔离其他不合作写入者。

按上一清单删除已从源集合移除且未被独立修改的受管快照，未知文件不删，源状态不删。无自动任务是有效状态。内容和受管集合不变不改 manifest 时间、不造空提交。

提交后核对真实提交字节；向明确分支推送后比较远端 SHA 与本地本轮 HEAD。命令退出零不单独构成成功证据。失败保留本地提交；显式 --push 可重试未推上的同一个检查点，不额外造提交。没有新 push 但 SHA 已一致时区分 pushed=false 与 remote_verified=true。

## 恢复

仍是比较合并流程，不提供假想全自动恢复命令。克隆或读取经授权的状态副本：账本按事件/追加记录合并，保留全部来源；索引按项目 ID 比较，复核基线来源/新鲜度；全局规则与自动任务先看差异。没有显式授权不得导入旧云端；当前 2.4 新状态与任何旧云端默认隔离。获准恢复 2.4 状态时，旧云端快照不能覆盖较新本地决定，关系不清楚就保留冲突。

源码和状态同步不是跨仓事务，各自报告本地提交、远端 SHA 和是否核验。一方成功不代表另一方成功。若只运行本状态脚本，不声称它顺带推送 Skill 源码。
