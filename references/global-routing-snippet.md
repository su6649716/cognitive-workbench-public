# 全局路由片段

只有用户明确要求安装全局自动路由时，才把下面内容合并进 `~/.codex/AGENTS.md`。保留已有规则，不整文件覆盖。

```markdown
## 认知助手路由

在非机械任务中静默检查一次，不向用户展示检查过程：

- 用户说“认知一下”“启动认知助手”“用认知助手看看”或显式调用 `$cognitive-workbench` 时，立即使用认知助手；先用一句话反馈已经启动、本次处理方式和是否直接执行，不要求用户选择内部工作流。
- 新建系统、应用或长期基础设施，或者既有系统新增模块、角色、状态、数据源并需要上下联动时，使用 `$cognitive-workbench` 的扩张检查。系统变化先恢复父系统目标并扫描必要联动，遵循“广思考、窄执行”；目的仍靠推断、存在多种产品形态、返工成本高或用户反复纠正时，在完整实施前进入共同定义与渐进开工。
- 不确定的原因判断或预测即将驱动实际行动时，使用 `$cognitive-workbench` 的假设追踪。
- 重要任务形成跨任务可复用的决定或结果时，使用 `$cognitive-workbench` 的任务收口。
- 只有用户明确要求或定时任务指定时，才使用 `$cognitive-workbench` 的多项目复盘。

没有明显触发信号时直接完成原任务。同一轮最多主动提示一次。用户说“直接做”或“这次跳过”后，对已经共同可见且语义明确的范围立即继续，不重复劝说；执行授权不把系统尚未展示的目的或产品形态推断变成用户决定。不自动用于普通问答、润色、小修改或无行动后果的随口观点；但用户显式说“认知一下”时仍正常响应，不为简单任务制造额外流程。

同一问题的重写、细化、执行和结果验证默认续接已有认知阶段；用户再次点名 Skill 不等于新建事件。扩张判断、用户决定和未来验证分阶段记录，不揉成一条事件。

当 `$cognitive-workbench` 已触发且任务会实质修改代码时，修改前读取其 `engineering-baseline.md`：精确解析代码项目根，缺少 Git 时安全初始化，把用户称呼、源码根、成品/运行入口和任务关联写入项目索引，记录 HEAD 与原有脏文件；中高风险项目进入样板或完整开发前，用项目索引的语义闸门确认目的、边界、方案和基线仍有效；语义完成并验证通过后，只提交本任务路径并运行工程收口检查。禁止在多项目集合目录初始化总仓库，禁止把用户原改动混入提交。云端推送仅在用户本轮明确要求或仓库设置 `codex.autoPush=true` 时执行。
```
