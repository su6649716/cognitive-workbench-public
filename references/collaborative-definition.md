# 共同定义：先做对，再逐步做完

## 职责与触发

目的的归属属于用户。本模块只处理返工昂贵的关键语义分叉，是 `expansion_gate` 的条件步骤，不是新工作流。主文件已经允许在同一目标、确认和授权内自主选路；技术选择不重复送审。

目的或组件边界仍靠推断；多种产品形态会改变使用、数据或交付；新建长期产品且关键选择尚不明确；高成本不可逆变更；用户多次纠正；代表性路径尚无法验证关键选择——先恢复已知，再处理未确认部分。清楚可逆的机械修改不进入。

## 来源与状态

| 字段 | 有效状态 |
|---|---|
| purpose_status | assistant_inferred / user_explicit / user_confirmed |
| boundary_status | draft / user_explicit / user_confirmed |
| design_status | draft / proposal_presented / user_explicit / user_confirmed / implementing / validated |
| sample_status | pending / accepted / not_required |
| baseline_status | current / stale / superseded |
| baseline_source | 可追溯的用户原话、任务或文档引用；非空字符串 |

`assistant_inferred` 是建议，不能当中高风险实施依据。用户已明确表达可记 `user_explicit`，无需重复确认；展示后被接受才记 `user_confirmed`。不需要样板须填 `sample_not_required_reason`。脚本只能验证字段，不证明确认真的发生。

## 一次共同定义包

简明展示：目的与来源、当前职责/边界、不变量、真正不同的方案竞争、推荐与代价、最强反对理由、低保真连续路径、代表性样板、阶段验收。只列一至三个真正影响路线的分叉，并附推荐；只有一条合理路线就不凑数。

## 渐进式开工

恢复理解 → 目的/边界明确 → 方案与流程明确 → 代表性样板 → 完整实施 → 工程验证 → 真实使用。阶段按实际风险选择，不要求每步停下来。已明确的部分直接通过，低风险可直接实施，非界面且样板无收益可说明原因后跳过。

“直接做”继承当时共同可见且明确的范围，不把隐藏猜测升级成用户确认。不能用此规则反复要求确认用户已经说清楚的内容。用户明确“全新重做、不沿用旧方案”，就是本轮有效决定；不能再以旧基线曾被确认为由恢复它或要求用户重新否定。仅确认新目标中仍不明确的重要分叉。

## 语义变化暂停

库、算法、性能、兼容或测试实现等技术不确定性，由助手自行核实并继续。新事实会改变目的、职责、已确认形态、业务规则、操作语义或重要验收时，把相关基线标成 `stale`，仅暂停扩大受影响的完整实现；展示新事实、修正推荐和必要取舍，未受影响部分继续有效。

## 闸门

保存有效规划后执行 `scripts/project_index.py gate --query <项目> --risk low|medium|high --target-stage sample|full [--user-facing]`；自定义索引用 `--index` 放在 `gate` 之前。

中高风险需要 current 基线、真实可追溯来源及用户明确/确认的目的、边界、方案；高风险面向人的 full 阶段还需接受样板或说明不需要的理由。低风险机械任务不制造基线仪式。闸门失败返回受影响的定义，不靠“已思考”绕过，也不把所有失败都变成向用户索取背景。

## 结果边界

共同定义降低理解返工，不证明产品有用。L1 工程、L2 忠实样本、L3 真实使用分别保留；后续真实反馈回到原规划，不作孤立补丁。
