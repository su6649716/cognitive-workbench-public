# 十三项能力在工作流中的位置

这些能力是局部认知算子，不是十三个并列Skill，也不要求一次全部使用。

| 能力 | 局部作用 | 主要工作流 |
|---|---|---|
| 信息溯源 | 追踪判断依据和来源距离 | 收口、假设、项目复盘 |
| 信息压缩 | 保留决定行动的最小充分结构 | 扩张检查、收口 |
| 事实观点拆分 | 分开观察、解释、预测和决定 | 假设、收口 |
| MECE拆解 | 建立与当前决定有关的问题空间；扫描系统传播层 | 扩张检查、项目复盘 |
| 因果分离 | 形成竞争解释和区分证据 | 假设、收口 |
| 逆向推演 | 找出失败路径和致命条件 | 扩张检查 |
| 链式推导 | 观察动作的上下游与后续连锁影响 | 扩张检查、项目复盘 |
| 第一性原理 | 从父系统目标、约束和不变量重建方案 | 扩张检查 |
| 假设验证 | 用现实动作降低不确定性 | 假设、扩张检查 |
| 瓶颈识别 | 找到当前最值得释放的约束 | 扩张检查、项目复盘 |
| 机会成本 | 比较被放弃的最佳替代项 | 扩张检查、项目复盘 |
| 止损预设 | 事前绑定未来的停止动作 | 扩张检查、假设、项目复盘 |
| 正反论证 | 主动寻找能推翻当前偏好路线的证据 | 扩张检查、收口、项目复盘 |

选择标准是当前认知困难，而不是能力覆盖率。输出必须落到局部结果：证据判断、最小验证、范围边界、保留结论或项目取舍。

需要让用户看见使用痕迹时，不展示“已调用某模型”的标签，而在任务收口中最多列 2～4 条可核对轨迹：`能力 → 当时依据的事实 → 因此改变的方案、范围或验证`。如果能力没有改变下一步，就不算实际使用；不能因为本表存在便声称十三项都已调用。

在系统一致性分支中，这些算子服务于“恢复目的与组件边界—规划连续任务—传播用户纠正—双向扫描—必要时转译界面—窄范围实施”，不是把十三项能力逐项展示给用户。目的规划和界面转译是组织这些算子的生产流程，不是新增第十四、十五项并列能力。

## 默认算子速查（先按这个起手，不够再加挂）

| 主工作流 | 默认带（起手） | 何时加挂 |
|---|---|---|
| expansion_gate | MECE拆解（问题空间+传播扫描）、逆向推演（失败路径）、瓶颈识别 | 目的靠推断时加第一性原理；多路线竞争时加正反论证；涉及取舍时加机会成本/止损预设 |
| hypothesis | 因果分离（竞争解释+区分证据）、事实观点拆分、假设验证（最小验证设计） | 长期测试加止损预设；多变量加链式推导（标注无法单独归因） |
| task_close | 信息压缩（最小充分结构）、信息溯源、正反论证 | 结论跨项目复用时加事实观点拆分 |
| portfolio_review | 瓶颈识别、机会成本、止损预设 | 项目间有上下游时加链式推导 |

起手三件套解决 80% 的认知困难。加挂要有理由：说清楚当前卡在哪、加挂哪个算子、期望改变什么决定。加挂后没改变决定，复盘时不列。
