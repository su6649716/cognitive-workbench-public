这些是可由当前目标替换的工程起点，不是行业强制标准，也不是要求原样继承的附件。全新建设按当前目标、使用场景和真实约束选值；维护任务才核实仍适用的现行规范。选择后落到本项目唯一真源；只在条件成立时引入结构。

## 运行边界与技术选择

| 条件 | 起始选择及落点 |
| --- | --- |
| 纯展示页面、浏览器本地处理 | 静态页面或客户端应用；没有实际需要不引入服务端、账号、云数据库。 |
| 单用户桌面工具 | UI 与本地业务、文件及供应商访问分开，经明确的本地调用或 IPC 接口交互。没有远程协作需求不配置云服务。 |
| 多用户共享数据、可信业务校验、服务端秘密或持续后台处理 | 增加必要后端；默认同仓模块化单体。浏览器不能直接持有服务端凭据或绕过业务权限写库。 |
| 已证实需要独立扩容、发布、隔离或多个客户端复用 | 划定独立部署边界，说明具体驱动因素；不要只因“前后端分离”就拆多个仓库或服务。 |
| 简单新 Web 工具且无技术约束 | 能用原生 HTML/CSS/JavaScript 完成则保持简单；需要明显组件状态管理时以 TypeScript + React 为起点，必要后端使用 TypeScript + Node.js。根据运行平台调整并选定一个具体方案。 |
| 需要持久化 | 单机结构化数据以 SQLite 为起点；多用户服务以 PostgreSQL 为起点；已有外部 SQL 则优先明确连接方式、读写权限和迁移责任。无需持久化则不建库。 |

使用选定工具的官方资料确认受支持且兼容的版本，固定运行时要求和依赖锁文件。所有模块使用同一套版本与构建来源。仅设计时可把版本锁定列为实现前动作；不要凭记忆编版本号。

选定目录，并写出真实职责与依赖方向。Web 的起点可为 `web/`、`server/`、`contracts/`；桌面可为 `ui/`、`core/`、`integrations/`。按工具惯例调整；小项目允许少量文件，不把目录数量当规范程度。

## 模块与数据

- 按业务能力组织模块。每个模块暴露小而清楚的公共入口，内部结构自行管理；跨模块调用公共入口。
- 为每类核心业务数据指定负责校验和写入的模块。共享数据库不等于允许所有模块随意写所有表。
- 实体、状态、权限、去重和业务不变量先以当前流程的真实例子确定。缺失的商业规则不得伪装成工程默认，例如收费金额、谁可审批、删除保留多久。
- 数据结构变更用版本化迁移记录。外部数据库非本项目管理时，标明可操作范围；不要擅自改上游表结构。
- 多用户系统在可信端校验身份及资源权限；前端显示或隐藏按钮不能替代权限校验。单用户本地工具不默认新增账号系统。
- 密钥使用平台凭据存储或受控运行配置，仓库仅保留无秘密的配置示例。测试数据与真实生产数据分开。

## 公共接口

- 每个公共接口指定一个权威契约源，例如项目已有 schema、OpenAPI 或共享类型定义；从它生成或导入使用方类型，避免手工复制多份字段。
- 无既定协议的普通 Web 请求以 JSON/HTTP 为起点：成功返回业务结构，列表统一为 `{ items, nextCursor }`，`nextCursor: null` 表示结束；错误统一为 `{ error: { code, message, requestId, details? } }`，同时使用匹配的 HTTP 状态。按业务规模决定是否实际需要分页。
- 本地调用沿用相同的业务字段和错误含义，可使用类型化结果；不为本地函数强行包装 HTTP。
- 错误 `code` 稳定可判定，`message` 用于解释，`details` 仅包含可公开的字段级信息。栈、SQL、供应商密钥等仅进入经过脱敏的内部诊断。
- 接口标识符用不透明字符串；跨系统时间用带时区的 ISO 8601，默认 UTC；金额使用明确货币的最小单位整数或约定精度十进制；时长统一毫秒。继承上游格式时在边界转换并记录。
- 前端集中封装服务调用、身份失效及公共错误解析；不同业务模块维护自己的业务载荷和规则，不强迫所有业务使用同一种状态模型。

## 界面与交互

先确定本轮需要的视觉方向和操作密度。全新设计不以旧主题和旧组件为约束；当前用户参考与明确要求优先。没有指定方向时，普通桌面 Web 工具可从以下取值开始，再按目标调整；选定后落实到唯一主题文件，控件直接引用。

| 项目 | 默认值 |
| --- | --- |
| 字体 | 系统无衬线字体，含适合运行平台的中文回退字体 |
| 字号与行高 | 正文 14px，辅助 12px，页面标题 24px；正文行高 1.5 |
| 间距 | 4、8、12、16、24、32px |
| 控件与圆角 | 常用输入和按钮高 36px，圆角 8px；触屏主要控件以至少 44px 为起点 |
| 基础色 | 页面 `#F7F8FA`，面板 `#FFFFFF`，正文 `#1F2329`，次要文字 `#646A73`，边框 `#DEE0E3` |
| 语义色 | 主色 `#2563EB`，成功 `#16803C`，警告 `#B45309`，错误 `#DC2626` |

这是起点而非视觉效果保证。根据品牌、阅读距离与实际对比度调整；保留键盘焦点、表单标签和不只靠颜色表达的状态。

统一当前需要的按钮、输入、错误提示、列表和弹窗；不要预建未使用的完整组件库。页面组合可以不同，同类操作的尺寸、禁用和反馈保持一致。

针对当前流程明确这几类状态：首次加载、无数据、执行中、成功、可重试失败、不可重试失败。短操作在原位置反馈，提交期间防重复触发；长任务有可找回的状态入口。删除、覆盖等难恢复操作根据影响提供确认或可撤销方式；普通操作不层层确认。

## 外部服务与长任务

供应商相关的认证、原始字段、错误和重试集中在对应接入模块。优先使用已有 SDK、HTTP 或 CLI；业务模块通过明确接口调用。仅对真实变化点增加适配，不为单一调用制造多层转发。

接入前确定：官方接口和身份方式、输入限制、返回结果、错误含义、超时、限流、费用和数据流向。未知项列为具体阻塞；没有凭据时可验证替身和契约，但不能宣称外部服务已连通。

- 普通元数据读取可从 10 秒超时起步；任务提交可从 30 秒起步，按上游实际约束调整。长任务完成时间不等同于一次 HTTP 请求的超时。
- 默认仅对已确认可安全重复的读取或幂等操作重试，最多额外 2 次，使用退避和随机抖动；遵守上游 `Retry-After`。有副作用的创建、付费请求和未知幂等能力的操作不盲重试。
- 超时后不能直接认定外部操作失败。可查询时用本地任务 ID、上游 ID 或幂等键核对；不能查询时标记“结果待核实”，为用户提供明确恢复动作。
- 存在需要跨请求或重启恢复的长任务时，持久化 `taskId`、上游引用和状态。状态起点为 `queued / running / succeeded / failed / cancel_requested / cancelled`；另设 `syncStatus: known / unknown` 表示观察是否确定。只在确认终止后写 `cancelled`。
- 进度未知时返回 `progress: null`；接口失败不伪造百分比。恢复时先核对既有任务再决定重提，避免重复处理或重复收费。
- 上游没有推送时，正在查看的任务可从每 2 秒查询起步；不在前台时降低到 10 秒或暂停。结合限额、平台行为和任务数量调整；终态停止查询。

外部托管 API 的服务端密钥留在后端。用户自行提供的桌面本地密钥存入平台凭据存储；确认第三方使用方式允许此调用模式。上传文件前说明实际数据流向，按用户用途确定保存和删除行为。

## 运行维护与用量

| 条件 | 默认落点 |
| --- | --- |
| 服务端运行 | 结构化日志输出到运行平台支持的日志通道；配置存活和就绪探针，避免把敏感诊断暴露给公网。 |
| 桌面本地运行 | 按平台约定保存应用日志并提供脱敏诊断导出；进程退出和重启后的未完成任务有恢复方式。 |
| 一次性脚本或纯静态页 | 保留适用的错误提示和构建检查；不默认引入日志服务器、守护进程或监控平台。 |
| 付费或配额依赖 | 记录调用数、用量及能够核实的费用；定义预算、限额及触顶动作。未知价格或预算不得解释成无限。 |
| 需要 Agent 参与维护 | 先提供已有日志、诊断命令或管理 API 的可用入口；只有实际调用方需要才新增 MCP。维护接口沿用身份和操作权限。 |

日志至少能按适用的 `requestId` 或 `taskId`、时间、版本、环境、模块和错误码定位；明确实际保存位置、轮转和保留期限。默认不记录密钥、完整私人文件或无必要的个人信息。

生产服务为实际风险选定少量信号，例如失败率、任务积压、外部限流或预算使用率。写出测量窗口、阈值、检查周期、具体接收位置与处理动作；低流量系统结合失败次数，避免单次失败误报。没有足够依据时标明待校准值及校准动作，不声称监控已经完成。

通知接收人、真实告警投递、收费服务开通和外部运维操作使用现有授权；先完成可审阅的配置，缺少授权的实际动作保持待执行。

## 交付和持续修改

- 本地工具明确构建、安装、配置、数据位置和升级方式；服务明确构建、环境、发布入口和版本识别。只设置实际需要的环境。
- 数据需要保护时写清备份对象、频率、位置、保留期与恢复命令。备份文件存在不等于恢复成功；恢复目标由业务影响确定，尚未确定的目标显式记录。
- 首次发布验证当前代码、配置和数据初始化即可，不预设旧系统迁移。更新确有存量消费者或数据的系统时，确认实际兼容责任；代码回退不能自动撤销数据变化，不可逆迁移须有恢复路径和授权。
- 维护者能找到依赖配置、已知限制、诊断入口和关键决定。项目文档引用代码中的事实，不复制快速变化的版本、字段和数值。
- 关键流程至少验证正常结果和最重要的失败情况；按风险补充权限、重复请求、重启恢复、跨模块兼容等检查。使用仓库已有测试框架，避免照抄实现的无效测试。
- 后续功能从当前任务已经建立的有效基线继续；用户明确重新设计时重新评估，不因旧文档存在锁死选择。修改共享规则同步实际使用方与验证；模块内部变动在模块内部完成。
