# 代码项目工程基线

## 目的

让高价值代码任务在修改前有可追溯起点，完成后有可恢复的本地提交，避免项目过几天才补 Git、把多轮改动混成一团。工程基线不是新的认知工作流，不向用户展示额外表单。

## 触发范围

仅在 `$cognitive-workbench` 已触发且当前任务会实质修改代码时执行。普通问答、只读审计、单句配置说明和非代码任务不初始化 Git。

## 修改前

1. 精确解析实际被修改的代码项目根目录。
   - 已在 Git 仓库内：使用现有仓库根。
   - 当前目录包含多个独立子项目：选择实际目标子项目；禁止在集合目录初始化总仓库。
   - 目标不明确：继续只读检查；不能安全解析时才问用户。
2. 运行 `scripts/git_project_guard.py --path <project> --init-if-missing`。
3. 若脚本拒绝初始化，按其原因处理，不绕过保护。
4. 检查 `.gitignore`、敏感文件警告、当前分支、HEAD、远程名称和修改前工作树。
5. 使用 `scripts/project_index.py upsert` 登记已确认的项目名称、别名、源码根、成品/启动入口、任务 ID、远程地址和当前检查点。只写真实存在且已经核对的路径；源码与编译成品必须分开。
6. 保存任务起点：目标、验收条件、HEAD、修改前脏文件、本轮任务路径和不碰的边界。存在认知事件时写入其 `metadata.engineering_baseline`；否则只保留在当前任务上下文，不为基线单独制造认知事件。
7. 若任务属于中高风险产品或系统改造，在首次进入样板或完整代码实施前按 [collaborative-definition.md](collaborative-definition.md) 更新目的、边界、方案、样板与基线状态，并运行 `scripts/project_index.py gate`。工程仓库已经安全就绪不等于产品语义已经确认。

## 新仓库

- 只有精确代码项目根、存在代码项目标识且不是宽泛目录时才允许 `git init`。
- 默认分支使用 `main`。
- 初始化后先完善 `.gitignore`，不要提交 `.env*`、密钥、凭证、依赖目录、构建产物或本地数据库。
- 现有项目第一次纳入 Git 时，只有在敏感文件检查通过、文件边界明确后才能创建初始本地提交；存在不明文件时只初始化并报告“首次提交待确认”。

## 执行中

- 记录任务开始前已经存在的修改；这些修改属于用户，除非本任务明确处理它们，否则不改、不暂存、不提交。
- 长任务在一个可运行、已验证的阶段完成后可以创建本地阶段提交，不创建失败状态或纯 WIP 提交。
- 不用 `git add .`、`git add -A` 或通配符打包未知变化；只暂存本任务明确修改的路径。
- 不为制造干净状态而还原、删除或覆盖用户改动。

## 语义收口

任务达到真实完成条件后：

1. 运行与风险相称的测试、构建或静态检查。
2. 运行 `git diff --check` 并复核工作树。
3. 区分任务改动和修改前已有改动。
4. 仅暂存本任务路径，检查 staged diff 不包含秘密和无关文件。
5. 若仓库未设置 `codex.autoCommit=false`，创建描述结果的本地提交。
6. 运行：

```text
scripts/git_project_guard.py --path <project> --check-close \
  --baseline-head <修改前HEAD或NONE> \
  --task-path <本轮路径> [--task-path <本轮路径> ...]
```

7. 只有 `closure.ready=true` 时才写“工程已收口”。否则写“功能完成但工程未收口”，说明尚未提交的本轮路径、无法提交的原因和下一动作。
8. 把提交号、验证结果、仍未提交的用户改动写入任务收口，并用新提交号更新项目入口索引的 `last_checkpoint`。

以下情况不自动提交：测试失败、存在疑似秘密、任务改动与用户原改动无法安全分离、提交会包含不明大文件，或用户明确说不要提交。

认知收口不能替代工程收口。项目文档、事件账本或聊天里已经写了“完成”，但本轮任务路径仍未提交时，工程状态仍是未收口。

## 云端推送

- 默认不创建 GitHub/GitLab 仓库，不猜测公开或私有，不修改远程地址。
- 只有用户本轮明确要求推送，或仓库设置了 `git config --local codex.autoPush true`，才允许推送。
- 自动推送还必须满足：已有明确远程、当前分支与目标明确、本地提交成功、没有需要用户决定的冲突。
- 推送失败时保留本地提交并报告原因，不反复改写历史。

项目可用下面的本地配置覆盖默认行为：

```text
git config --local codex.autoCommit false
git config --local codex.autoPush true
```
